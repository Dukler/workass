La race ocurre entre el barrido del reaper y la comprobación de lastActivity. El reaper lee el timestamp, decide hibernar y después toma el lock — para entonces ya llegó un prompt nuevo, pero el engine se reap igual.

La comprobación y la acción no son atómicas. Entre el RLock de lectura y el Lock de escritura hay una ventana donde markActive() corre desde otra goroutine:

// reaper.go — barrido cada 30 s
func (r *Reaper) sweep() {
  for _, s := range r.idleSessions() {   // lee bajo RLock
    if time.Since(s.lastActivity) > idleTTL {
      r.hibernate(s)                     // toma Lock — ¡tarde!
    }
  }
}

Bajo carga (10+ chats) el reaper hiberna sesiones con prompt en vuelo. La política correcta:

Estado del chatPolíticaAcción del reaper
Prompt en vuelopinNunca hibernar
Idle < TTLkeepMantener caliente
Idle > TTLreapHibernar y replay
