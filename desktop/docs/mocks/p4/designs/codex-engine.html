Encontré la race. El barrido corre en su propia goroutine cada 30 s y decide hibernar leyendo s.lastActive sin tomar el lock, mientras el bucle de turnos actualiza ese mismo campo cuando llega actividad. Entre el chequeo Since(lastActive) > idleTTL y la llamada a hibernate(s) hay una ventana en la que un turno nuevo marca la sesión como activa, pero el barrido ya decidió dormirla — y gana el barrido.

El bug vive en sweep(): lee el mapa bajo RLock, pero suelta el lock antes de hibernar, así que el estado que evaluó ya está viejo cuando actúa.

go daemon/reaper/reaper.go 
// sweep evalúa cada sesión y decide si hibernarla.func (r *Reaper) sweep() {    r.mu.RLock()    for id, s := range r.sessions {        if time.Since(s.lastActive) > r.idleTTL {            stale = append(stale, s) // decisión tomada aquí…        }    }    r.mu.RUnlock() // …pero el lock se suelta antes de actuar    for _, s := range stale {        r.hibernate(s) // s.lastActive pudo cambiar aquí    }}

Voy por la primera: el barrido sigue siendo barato, y agregamos una re-verificación de lastActive dentro de hibernate tomando el lock de escritura, de modo que cualquier actividad que haya llegado en la ventana cancele la hibernación.
