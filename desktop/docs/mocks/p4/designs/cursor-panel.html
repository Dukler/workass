Confirmado: hay una race de tiempo-de-uso vs tiempo-de-chequeo (TOCTOU) sobre s.lastSeen. El barrido toma un snapshot del mapa bajo RLock, pero después lee s.lastSeen fuera del candado. Si un turno del agente llama a markActive() justo entre el snapshot y el chequeo, sweep ve un valor viejo e hiberna una sesión que sigue trabajando.

La escritura y la lectura de lastSeen no comparten sincronización, así que el fix mínimo es hacer atómico ese campo y decidir la hibernación con un compare-and-swap del estado:

Go daemon/reaper/reaper.go 
// lastSeen ahora es atómico (UnixNano)
func (s *Session) markActive() {
    atomic.StoreInt64(&s.lastSeen, time.Now().UnixNano())
    s.state.CompareAndSwap(stateIdle, stateWorking)
}

func (s *Session) idleFor(now time.Time) time.Duration {
    last := atomic.LoadInt64(&s.lastSeen)
    return now.Sub(time.Unix(0, last))
}
