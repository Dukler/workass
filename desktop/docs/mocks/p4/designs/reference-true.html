Race del reaper de hibernación ··· daemon/reaperrama fix/lease-pin
El reaper está hibernando chats que todavía están trabajando. Encontrá la race y proponé un fix. daemon/reaper/reaper.go
▸Pensó 8 s · revisó el bucle del reaper y el registro de leases

La race ocurre entre el barrido del reaper y la comprobación de lastActivity. El reaper lee el timestamp, decide hibernar y después toma el lock — para entonces ya llegó un prompt nuevo, pero el engine se reapea igual:

  • La comprobación y la acción no son atómicas: entre el RLock de lectura y el Lock de escritura hay una ventana donde markActive() corre desde otra goroutine.
  • Bajo carga (10+ chats) la ventana se cruza varias veces por hora.
// reaper.go — barrido cada 30 s for _, s := range r.idleSessions() { // lee bajo RLock if time.Since(s.lastActivity) > idleTTL { r.hibernate(s) // toma Lock — ¡tarde! } }
▸Leyó 3 archivos, corrió 2 comandos

El fix: fijar (pin) el lease mientras hay un prompt en vuelo y re-verificar lastActivity ya con el candado de escritura tomado.
