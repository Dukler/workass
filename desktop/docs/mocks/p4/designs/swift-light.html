Confirmado. El reaper decide hibernar mirando solo s.lastActive, pero una sesión puede estar corriendo una herramienta sin haber tocado ese timestamp. El barrido lee lastActive fuera del lock que protege el estado de la sesión, así que compite con markBusy(): si el Tick entra entre la comprobación y el SetTool, la sesión activa se marca como inactiva y se hiberna.

go daemon/reaper/reaper.go · sweep() 
func (r *Reaper) sweep(now time.Time) {
  for _, s := range r.sessions() {
    // lee lastActive sin el lock de la sesión ⚠
    if now.Sub(s.lastActive) > r.idleTTL && !s.busy {
      s.Hibernate()   // puede matar una sesión en pleno trabajo
    }
  }
}
